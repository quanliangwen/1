一、简历可直接使用

参与设计面向多核神经网络处理器（NPU）的计算图切分与调度算法，在算子依赖、片上存储容量及共享 DDR 带宽约束下，联合优化子图粒度、核心映射和执行顺序。以事件仿真轨迹中的核心空闲、缓存换入换出及跨核搬运定位瓶颈，结合多层次子图重构、流水线空闲时隙插入和共享 L2 缓存感知排序迭代改进方案。在 100 个赛题算例上，团队方案相对单核基准实现 5 核平均 4.905 倍加速（共享只读 L2 场景），获全国三等奖。

简历分点版

• 参与设计计算图切分、核心映射与核内排序的联合求解流程。利用事件仿真识别核心空闲、片上存储溢出和跨核传输热点，针对瓶颈重构子图，并以 Fiduccia–Mattheyses（FM）方法微调优质方案的切分边界。
• 参与设计硬件感知调度策略。按算子依赖与数据到达时间，在对应流水线中寻找可容纳算子的最早空闲区间。结合 Tensor 生命周期和共享 L2 的 FIFO 驻留窗口，调整可复用数据的访问顺序。
• 团队在 100 个赛题算例上完成 2–5 核仿真和代表性算例消融。5 核下，独立任务、同核数据驻留、共享只读 L2 三个场景相对单核基准的平均加速比分别为 3.935、4.693、4.905 倍，获全国三等奖。

二、问题背景

神经网络计算图由算子和张量组成，可以表示为有向无环图（DAG）。切分过细会增加子图交界处的 COPY 和等待，切分过粗会减少可并行任务，还可能抬高 L1/UB 占用。分核及执行次序也会改变跨核搬运、计算与访存的重叠程度，以及张量能否在片上复用。项目在独立 Task、同核数据驻留和共享只读 L2 三种赛题场景下，求解如何切图、如何分核及如何排序，使整个计算图的总体完成时间（Makespan）尽量短。

三、算法设计贡献展开稿

1. 联合建模和候选评价
参与建立“搜索候选调度—确定性事件仿真—反馈更新”的求解流程。上层候选由子图划分、核心归属和同核执行次序组成。通过对算子覆盖、核心唯一分配以及数据依赖和执行次序构成的增广图做可行性检查，避免循环等待。事件仿真追踪算子就绪、流水线占用、L1/UB 分配与溢出、跨核同步及共享 DDR 请求进度。候选按词典序比较，先最小化 Makespan，耗时相同时再比较额外 DDR 搬运量，从而保持搜索目标与赛题评价一致。

2. 执行反馈驱动的子图重构与边界优化
参与设计从仿真结果中选择重构区域的方法。根据其他核心的累计空闲、核内 spill（换出及重新换入）和跨核 COPY 字节数给区域排序，选择局部区域并撤销旧边界。区域约覆盖全图 5%–20% 的计算算子。在支持同核驻留的场景中，从原始算子出发，按直接依赖和共享张量关系重建多个粒度，每个层级分别重新分核、排序和评估。用 FM 方法在优质结构附近移动边界算子，以基础搬运量变化筛选移动，再由完整仿真判断最终收益。当前方案可暂时进入较差结构以继续探索，历史最优方案独立保存。

3. 流水线时隙插入与张量生命周期调整
参与设计同核复用场景下的核心映射策略。以结构块为分配单位，按剩余关键路径选择就绪块，并对每个候选核心逐算子估计依赖就绪时间，在对应流水线中找到能容纳该算子的最早空闲区间。综合结构块预计完成时间、基础 DDR 搬运时间和流水线最大负载选核，再用算子预测开始时间指导合法排序。针对回放中实际发生的 spill，依据张量两次相邻使用的位置生成前移或后移候选，尝试缩短复用间隔。结构与映射阶段使用关键路径、流水线负载和通信量下界筛除确定无竞争力的方案，保留 Makespan 持平时进一步减少搬运的机会。

4. L2 缓存感知排序与仿真复核
参与设计共享只读 L2 条件下的访问重排策略。第一种方法按 L2 容量组织跨核共享输入工作集，在满足依赖的就绪算子中优先安排访问相同输入的算子。第二种方法从缓存插入与淘汰事件还原 Tensor 的实际驻留窗口，在原 DAG 允许的范围内调整相关算子的执行顺序，使跨核读取有机会落在数据仍驻留的时间段。仿真按 COPY_IN 实际发射时刻判断命中，并分别处理 DDR 与 L2 的带宽竞争，最终用全量回放比较 Makespan 和额外搬运量。以缓存字节命中率解释数据复用情况。

四、量化结果与统计口径

• 100 个赛题算例均以同一算例的单核完成时间作为加速比基准。三种场景在 2/3/4/5 核下的平均加速比分别为：
  独立 Task            1.906 / 2.710 / 3.353 / 3.935
  同核 Tensor 驻留     2.326 / 3.266 / 4.085 / 4.693
  共享只读 L2          2.342 / 3.318 / 4.183 / 4.905
• 5 核下，共享只读 L2 场景的平均加速比为 4.905，对应无 L2 场景为 4.693，平均加速比相对提高 4.52%。这是两种硬件配置分别优化后的比较，包含调度方案变化。共享 L2 场景的 5 核平均缓存字节命中率为 22.73%，分母为可由 L2 服务的读取字节数。
• 算例覆盖从 2,500 个及以下到超过 20,000 个计算算子的规模。代表性消融显示，局部子图重构在部分算例中明显改善初始切分，流水线空闲时隙插入在所选的两个同核驻留算例中均带来收益。实验数据来自赛题执行模型的仿真评估。

五、面试口述版（约 1 分钟）

我参加“华为杯”研数模做的是多核 NPU 调度，项目获全国三等奖，我主要参与算法设计。这个问题有一个典型权衡：切图细了更容易并行，但会增加跨核搬运，切图粗了又会占用更多片上存储。我们把切图、分核和排序放到同一个搜索框架里，先根据关键路径和流水线空闲区间构造方案，再用完整事件仿真找到核心空闲、数据换入换出和跨核搬运的热点。根据这些反馈重构局部子图，并在共享 L2 场景里调整访问顺序，让不同核心尽量在张量被淘汰前完成复用。团队用 100 个算例验证，5 核共享 L2 场景相对单核平均加速 4.905 倍。

六、面试可展开的两个设计点

• 为什么要把局部估计和完整仿真放在同一流程？关键路径、数据搬运量和流水线负载便于低成本筛选候选。改动局部次序却可能同时改变张量存活区间及多个核心的带宽竞争。完整事件仿真负责确认这些联动影响，决定最终方案。
• 如何在有限求解时间里扩大搜索范围？先根据仿真轨迹选热点，仅在局部拆散边界并生成多个聚合层级。用关键路径和工作量下界筛掉明显较差的层级，将完整仿真预算留给更有潜力的候选。保留历史最优的同时允许改变当前结构，有助于摆脱初始划分的限制。
