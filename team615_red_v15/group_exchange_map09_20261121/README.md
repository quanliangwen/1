# 潜力1.1：分组返航与择图提交候选 / Map09，种子615

这是研究候选源码和一次隔离SDK测试记录，不是正式比赛提交包。没有上传官网，没有测试其他地图。正式采用前应根据下方实测结论决定。

## 实施范围

基线为潜力1.1原版，ZIP SHA256：`c3021a3eb48031e82bfac9306654b48ca09f168d6f65b13349cf12f783104c7c`。
修改`red_hooks.py`和`fast_closeout.py`，新增`exchange_plan.py`、`group_exchange.py`、`map_candidates.py`。其余51个文件与原版字节相同。投放复核、导航驱动、地图拟合参数、DeadlineSubmission硬触发条件没有修改。

- 60%以后，已空仓且无在途投放/脱离的飞机，先只读检查共享计划、路线和预算，再取得导航所有权。检查失败不取消原信使、不清空原导航任务。
- 探索期间记录真实直接通信与分支历史；支持实际分组，不固定3+2，不固定0号收图或交图。
- 0号只承担早期共享父区域元数据的临时发布者；发布不要求五机同时距0号150px。各机分时确认已知返航入口，才形成全队共享计划。
- 局部先交互，再由实际持图者前往共同父区；已交付成员保持并保留原避障。没有双方确认的新C点时，不各自猜中点。
- 每个epoch最多一个返航任务，阶段只向前推进，广播不重启任务。迟到且返航超预算的机器保留原导航，可在实际接触时被动交付。
- 冻结地图与方向证据的一致版本。只有实际校验保存的快照/图像才产生对应收据；按对方缺口发送一种载荷，重复载荷不重复合并。
- 保留5张个人图和最多1张融合图，用共同证据估计质量；真正持有获胜图的机器可代替原作者提交。
- 新出口绕过旧扫描、快照等待和普通竞价等待，保留库存、pending、非空图和部分图检查。快收尾普通提交受协同门控，投放动作保持原样。
- 软截止为85%步数（5400时4590）或墙钟剩余8秒；截止释放协同导航/普通提交门控。原步数和墙钟硬兜底优先，选中图同步进入兜底缓存。

## 设计落实时的具体选择与限制

1. 父区域的早期发布采用本机离开初始轨迹点80px、定位可靠、网格已知安全的参考条件；它不表示已识别真实道路岔口，也不保证父区域已经远离整个队伍的初始区域。A/B再由实际分支接触记录选择。这个近起点后备点可能增加绕路，必须结合本局坐标与返航证据评价，不能称为最优中间点。
2. 分支稳定参考值40步；局部组在前1600步或总步数30%以内的历史中识别，不依据真实地图拓扑。实际若没有有效A/B，则用共享父区；若没有全队共享计划，则不接管原导航。
3. 共同父区域要求可沿已知通道进入距离父点80px内，使两个携图者即使没有0号在场仍有机会互通。此距离只作为通信区域几何余量，不能代替真实收包。
4. 返航ETA按已知路径长度/2加40步估算，属于启发式。旧轨迹离线估算只用于预算预警，不保证新轨迹到达时间。
5. 图质量使用原`local_score`，不是官方真值地图分。断联时只能选择当前持有的候选；没有声称保证全队官方最高分。
6. 达到协同截止且库存已真实清零时，可对已持有图选择后提交；仍缺的来源必须保留在审计中。不能把超时交图写成全队地图收齐。
7. 新策略会改变相遇与让行，即使投放函数原样保留，末弹仍可能间接受影响。本局会逐机对照。

## 校验与复现

36组合成反例通过，实际导入候选ZIP内控制器，禁止`pymunk.Space.step`调用；无物理步、无地图实例、无整场。官方静态内容检查及当前只读复用环境的NumPy随机数/Pandas/OpenCV实际运算通过。详见`VALIDATION.json`、`counterexamples.json`和证据包。

`CANDIDATE_SOURCE.zip`是完整56成员的研究快照；`group_exchange.patch`用于原版目录。不要叠加到3240直接交图版或旧单点会合版。基线到候选的逐文件哈希、方法AST变更见`RESULTS.json`中的`candidate_build`。

整场使用封存官方SDK提交`6557940dc18549ffc7a945db887da5b05b7ed2f1`，Map09、种子615、5机各2弹、5400步/180秒，禁GPS和禁通信区均开启。只新增一局红队测试；原版及旧单点候选是已保存的同种子历史结果。红队80分小计不包含未测的蓝队20分，不能冒称总分100分。墙钟比较受机器负载影响。

`RUN_EVIDENCE.zip`含候选原始评分、轨迹、事件、源码绑定、反例、当前环境检查与复现脚本，并含原版关键评分/事件。新整场开始后没有再修改候选源码。

## 会合与提交证据

**本次没有完成设计目标，不能把涨分称为分组加速成功。**

能确认的事实：

1. 第81步提出共享父区域，估计坐标约`(607.28, -286.20)`，最后5机均接受。同一共享根点问题已经解决，但点位靠近初始区域，不是经过验证的首次分叉点。
2. 0、2、4号3240步开始，3号3277步开始；分别在3360、3354、3381、4101步退出。退出意味着当前网格检查连续拒绝连接、原寻路未提供可用连接，不等于真实地图上没有路。
3. 局部分组没有形成共同版本：0/2/4保存`[0,2,4]`，1号保存`[1,2]`，3号保存`[0,2,3,4]`；2号同时出现在不同组。0号的局部点约`(393,-346)`，2/4号约`(540,-441)`。这是实现没有闭合的地方，不是“仿真随机”解释。
4. 4171步0/4号互收冻结快照，4173步互收候选位图，4172～4175步收到对应实际保存收据。实际载荷校验与去重路径在本局确实工作，但发生在返航退出后，不是完整A/B/C会合。
5. 1号4447步才确认末弹，被预算检查拒绝返航；4447步冻结快照、4451步形成候选，但没有送到其他机。0号最后仍把1号库存记录为`(2832,1)`、3号为`(2804,1)`，普通交图条件不成立。
6. 全队没有形成择图提案，旧三道等待的绕过在本局没有实际触发。4970步使用原墙钟硬兜底；最佳图候选选择只通过合成反例，不能声称已获本局实战验证。
7. 前3237个记录帧与原版一致；首个轨迹差异在记录帧3238，约对应3241步，符合60%后接管。9枚实际落点与原版相同，只有1号末弹由原版`(-208.90,-440.23)`改为`(-127.85,276.53)`，实际生成步数从4026变4446。这说明源码保留投放复核，并未保证投放时序及落点不受间接影响。

推测及证据边界：

- 历史路径与当前网格/定位不一致可能造成短连接被拒绝，但现有观察未保存各次失败的网格局部状态，不能断言是哪一堵墙或哪项定位误差导致。
- 涨分同时伴随轨迹、通信、地图证据及1号末弹位置变化，不能把全部收益归给快照交付。墙覆盖分上涨与实际弹布局变化相符，但没有做隔离消融。
- 1号位置约3289步开始偏离；当时其余机在真实位置上均距它485px以上，不能直接归因为当场被其他机挤挡。原算法含墙钟门槛和按墙钟预算求解，精确因果仍未隔离。


## 使用建议

**目前不建议把它作为“加速版”替换原版。** 本次红队小计提高5.399分，但交图晚450步、1号末弹晚420步，且完整会合和择图没有发生；单种子涨分不能代替机制验收。

后续如继续，应优先补齐“同组成员与同一A/B点的共同确认”，再查清历史路径为何被当前连接检查拒绝；不要先叠加更多超时、几何阈值或扩大多图测试。当前候选和失败证据原样保留，本轮不做测试后的算法改动或追加仿真。
