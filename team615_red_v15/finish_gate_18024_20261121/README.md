## 本次行为

比较缓存与结束比赛分别处理。到60%且本机实际空仓、无pending时，比较缓存继续工作；不要求5份地图收齐，也不等待全队末弹确认才缓存。真正普通提交仍要求全队库存确认、本机无pending、现有窗口和部分地图检查通过。

新增普通结束门槛，直接读取原有常量：

```python
finish_floor = min(
    drone.pre_submit_scan.finish(drone) + FinalMaps.COLLECTION_STEPS,
    DeadlineSubmission.window_start(drone.limit),
)
```

5400步时为`3240 + 180 + 24 = 3444`。这是绝对步数基准，不从收齐某条消息时重新计24步；重复消息不延后门槛。所有返航中、退出返航和其他状态遵守同一普通交图门槛。旧普通及快收尾普通出口也不能因ABORT绕过它。

墙钟剩余少于原有12秒余量时让行该留时，使用已有候选，不额外进行终图绘制。原硬兜底仍在control最前段优先运行，最后30步窗口保持可达。

普通结束条件首次满足且预算充足时，将最新live memory与已有FinalMaps快照融合，用原渲染器重画一次当前候选；方向证据采用该时刻已收到/已观测的内容。先前最佳缓存、个人原图仍参加同一证据下的比较，新图不直接替换旧最佳。

正常路径的结束检查放在该帧原有观测、方向证据更新和地图缓存刷新之后、返航导航提前return之前。旧信使若提前return，也调用同一结束检查，使用当时已有证据，不额外补扫描，避免再次出现资格不一致。

终图重比通常会保留现有2步比较稳定期与2步提案确认。因此3444是放行下限，不保证真实比赛正好3444步结束。夹具演示3444重比、3446提案、3448提交；**这些仅为合成反例时刻**。

## 旧图保护和缓存细节

- 槽0～4仍为不可覆盖的个人冻结原图。
- 槽5为本机当前/融合图。
- 槽6仅在终图重画前保留此前选中的当前图；它不作为第六架无人机，不参与跨机快照/个人图广播。
- 新终图若更差，可选择槽6旧最佳；新图为空时不清除有效旧图。
- 同一步普通备份已生成图，也不能阻止终图更新；终图以force方式重置该次比较签名，避免“已经渲染但未比较”的同版本问题。
- 终图最多重画一次，重复控制调用不会每帧重拟合；正常实时缓存更新仍照常进行。
- Map09式全队末弹确认不齐时，不触发终图绘制或普通提案，4230/4590步已有新图仍可比较并进入硬兜底缓存。此前软截止后复用已生成实时图的修复保留。
