## 是否误让行及提交依据

本轮未出现新增首轮30步规则造成的误让行。Map06没有进入普通交图阶段，最终仍由墙钟硬兜底结束；三图候选的实际提交地图完整保留。

- 0～4号ordinary_selection均为False，最终重比、普通提交提案和普通分组交图事件均为空。该标志在本轮控制器初始化后不会从True重置成False，因此不是仅观察到结束时未就绪。
- 0号仍只知道3号2678步库存1枚、4号1791步库存1枚；1号存在相同缺口，2号还缺0号清零确认，3/4号仍缺1号清零确认。原_all_inventory_empty()要求五个ID都已记录为0，普通交图在新增让行判断之前就被挡住。既有真实库存信息按源时间更新，不会因为重复旧快照恢复成新状态。
- 5082步，0～4号均执行walltime硬兜底，SDK采用0号图；没有普通6步时间槽并发提交。五机应急同帧提交为原有保留行为。
- 0号采用4995版槽5缓存，实际位图SHA256为c710c5bdc5b0bc96596701e75ee28639e26176a1259ddad3b655db4c04731212，与三图候选实际提交图逐像素相同。地图分89.1569、漏墙8453、误画20040、探索率99.3744%、10枚实投及总掉血7均相同。
- 相对三图候选，小计53.9140比53.4536高0.4603，全部来自少174步的时间项。两局墙钟均约178.6秒，仅差0.016秒；这不能证明新增让行主动提前交图或实现计算加速。
- 相对潜力1.1原版，小计低1.1246，地图分低0.1868，墙覆盖低0.5134；漏墙多128、误画多1127，探索率和实投数相同，掉血少1点。仍未超过原版Map06。
- 与三图候选的机体、炸弹录制状态在前5080帧一致，首个不同帧为本局结束附近的5080帧；投放确认步数也完全一致。没有发现新增规则导致导航或投放过程退化的迹象。

本轮只新增这1局Map06，没有运行近分＋6步时间槽版本的Map06，也没有重跑其他地图。上述结果支持“本局没有误让行、已有地图质量未退化”，不把整候选相对三图版的时间分差单独归因于本次30步规则。

## 文件及边界
