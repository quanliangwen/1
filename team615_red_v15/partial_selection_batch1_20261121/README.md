## 结果判断

**本批功能已经实战触发，但尚不能认定为全图提分版本。**

- Map08：1号3245步从统一入口提交，原版/当前版均3444步。相对当前版提前199步，得分下降0.9120，地图分下降2.8769；相对原版得分下降2.4322。10枚全部实投、末弹确认步数不变，掉血较当前版少2。地图项损失1.4384分，仅换回时间项0.5265分。
- Map08实际提交74.3123分的当前图；离线评分中0号个人图72.8194、1号个人图73.6603、0号当时融合图72.1323。最终提交图确实是本局保存候选中的最高分。这排除了“仅因退队拿到资格、盲目放弃更好的已有0号图”这一旧问题；但全队后期信息尚未到达，早结束仍牺牲地图分。不能将“已有候选里最好”理解为“未来继续收包也没有收益”。
- Map09：0号4853步墙钟兜底交图，当前版4970、原版4520。新得分42.8892，比当前版高0.0312，属于基本持平；比原版高5.4302。地图66.0303，比当前版低1.0550，比原版高8.9423。117步减少不构成主动提前交图成功，墙钟仍约178.6秒。
- Map09在3240步仅有本机快照时就开始比较，4171步收4号快照、4173步收4号个人图后更新候选；4591步再次比较已生成的4590步实时图。实际提交图版本4590，修复了首轮停留在4231步的问题。由于仍缺全队末弹确认，普通提案/早交没有触发，比较结果用于原硬兜底。
- Map09中0号个人冻结图离线40.6506，收到的4号个人冻结图50.7278，本机最新当前图66.0303；最终选中了保存候选里的最高分。个人原图没有被融合覆盖。这个数据支持保留原图并比较当前图的机制，但不同时间、不同收到信息的图不能当作严格的纯通信消融。
- 两图合计13份个人图持有记录的摘要均与首次构建或实际接收时一致；实际选中缓存与SDK提交位图SHA256一致。资格、已有候选比较、缓存和原图保留已得到反例及真实数据验证。
- Map09的1号末弹4344步确认，当前版4447、原版4027；源码投放复核没有修改，但含墙钟预算的原逻辑仍可能因用时和相遇变化改变时序。不能把得分0.0312的小幅上涨归因于择图修复。

当前最明确的新边界是：**不等5份图进行比较成立，但库存清零加60%窗口就立即交图，在Map08仍然过早。** 下一步如继续，应分开处理“随时比较缓存”和“何时允许结束比赛”，避免重新回到等5机收齐，也不宜据此加严扫描过滤。本轮不再改代码或追加仿真。
