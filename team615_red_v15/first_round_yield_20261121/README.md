## 实现与边界

56个成员，只改`group_exchange.py`，其余55个文件字节一致。

新增`yield_first_round(drone, step)`，条件是：

1. 使用`drone.final_maps.snapshots`计数，少于2份才让行。分组候选池的快照数不替代它。
2. 时间区间为原`finish_floor`到`finish_floor + team_size × 6`，左闭右开。当前5机/5400步配置为3444～3473步，3474步解除新增让行。
3. 墙钟剩余不足12秒，或已进入原最后截止窗口时，不新增让行。恰好12秒仍按普通首轮规则执行。
4. 第二份最终快照到达后立即不再受此规则限制，仍须遵守实投确认、原有竞价和本机6步时隙。

只在两个现有函数各增加一次检查：

- `try_submit()`：放在原缓存比较、库存/pending检查、原有窗口、0.003最终选图和ready更新之后，发提案/普通提交之前。
- `ordinary_submit_allowed()`：让旧普通交图、ABORT后的出口和FastCloseout也服从相同规则。

没有新增本地计时器或重试状态。重复广播、新比较、晚到的普通交图资格都不会把30步重新启动。此规则只延后结束比赛，现有扫描、导航和缓存仍照常执行。

移除新增的两行调用后，两个旧函数的AST可完整还原基线；GroupExchange其余所有旧方法AST相同。`map_candidates.py`、`red_hooks.py`、FinalMaps、竞价、投放复核、双时限、导航与拟合代码均未修改。消息结构和收发实现未改，没有竞价转发。
