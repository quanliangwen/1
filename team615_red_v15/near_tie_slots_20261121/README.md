# 普通交图近分选新图、原有竞价让行与6步时间槽

已在冻结的180＋24候选上实现本批最小修改。89组反例和官方静态内容检查通过；没有创建地图、没有执行物理步、没有跑整场仿真，也没有新的Map08/Map09成绩。

基线SHA256：`2555f9585aa0fcb41874b44076ee34719c13dc314fc05de58e5e58be40cef19e`

新候选SHA256：`f2c1059afc5218bd19cea9995679492b8c2211fd2eae42d0f77caa9abbbab318`

## 修改范围

56个成员，只改`map_candidates.py`和`group_exchange.py`，其余54个文件字节一致。导航、探索、扫描、地图拟合、投放复核、双时限兜底的源文件及RedHooks整体字节不变。

- `MapCandidates.select_candidate()/choose()`：普通交图模式先取最高F1，在其0.003范围内优先版本最新候选；同版本仍按原分数、owner、digest稳定排序。普通模式以外完全沿用原F1排序。容差从最高分划定，不做逐对放宽，防止误差累积。图像渲染、参考证据构造和P/R计算均不改。
- `GroupExchange.refresh_comparison()/try_submit()`：全队实投确认、本机无pending、原有窗口和180＋24留时通过后才进入普通选图模式。模式持续到交图，后续缓存刷新不会退回旧排序。个人原图和旧最佳继续保留；进入模式会强制重比一次，最终绘图仍只做原有一次。
- `try_submit()/ordinary_submit_allowed()`：恢复调用原有`_prefer_own_submission()`，提案与实际交图前都重新判断质量竞价和限时让行。已有竞价代码未改。普通资格就绪时补齐原有bid的ready时间，返航状态不影响竞价资格；未确认全队清零不能变为ready。
- `submission_slot()`：以公共绝对步数为准，`((step - finish_floor) // 6) % team_size`决定时隙所有者。5400步局仍以3444为起点；5机30步一个周期。低墙钟允许提前放行时沿同一周期向前计算，不另起本地计时。
- `try_submit()/valid_choice()/receive()`：撤掉“新鲜邻机内最小编号自行领权”，改为只有本机时间槽才可发提案或普通交图。提案租约不跨槽，最后两步不新开提案，重复/过期提案不能锁住下一架机。receive仅增加对该公共时间槽的校验，不改实际地图收包逻辑。
- `ordinary_submit_allowed()`：旧普通交图和FastCloseout出口也经过时间槽及原有竞价检查；返航结束、ABORT或软协调截止都不能绕过。硬步数/墙钟兜底依然先于这些检查执行，不等时隙或竞价。

纯时隙错峰最多增加29步等待，不包含原有竞价让行和提案确认所需时间。不会重开180＋24步留时，不等待五份地图或全队ACK。时间槽提供普通提交互斥，无法让断联飞机得知全局真实最高分。

## 检查与文件

官方静态内容检查PASS；在只读复用Python3.11.17环境执行真实NumPy1.26.4的mtrand/RandomState、Pandas3.0.6、OpenCV4.11.0.86运算通过，SDK225个文件哈希核验通过。未安装或替换依赖，未声称官网镜像验证。

`CANDIDATE_SOURCE.zip`为研究源码快照；`near_tie_slots.patch`只适用于SHA256为2555f958…的180＋24基线，不可直接套在更早版本。两个修改文件单独提供。不是新正式参赛放行包，未上传官网。

`RESULTS.json`包含配置、89组结果和明确为null的新地图成绩；`VALIDATION_EVIDENCE.zip`包含完整验证脚本、原始日志、基线快照和补丁。`MAP08_SAVED_TABLES.json`记录旧评分表来源和哈希；`CHECKSUMS_SHA256.json`校验所有其他交付文件。

当前证明的是选图和提交权限契约，不保证0.003在其他地图总能提高官方分，也不保证真实Map08由1号执行。Map09原有缓存与硬兜底路径的反例已通过，真实比赛收益仍未复测。
