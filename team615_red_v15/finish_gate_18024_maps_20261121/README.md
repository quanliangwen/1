## 结论与限制

这版暂不建议替换上一版三图候选。留时和最终重比的控制逻辑已生效，Map08得分仍下降；Map09保住已有地图质量，但没有摆脱墙钟兜底。

**Map08能确认的事实：**

- 3240步开始比较缓存；0、1、3、4号在3444步执行最终重比；0号和1号均在3446步各自提出提交、3448步同时提交。此前3245步提前结束的问题已挡住。
- 本轮地图分72.8194，较本批最终版74.3123下降1.4930，红队小计下降1.2835；较上一版三图候选地图分下降4.3699、小计下降2.1955。
- 0号最终提交3240步个人原图（槽0），官方地图分72.8194。其3444步新图为73.2007，但在线代理分0.950324低于个人原图0.952670，因此没有选新图。
- 1号同机同时持有3444步新图77.1892和3274步旧图74.2805。在线代理分分别为0.949814和0.950368，所以选择了保留在槽6的旧图。该77.1892新图的位图SHA256与上一版三图候选实际提交的图一致，说明补进信息和原拟合得到的新图并没有丢失。
- 0号、1号的提交内容不同。SDK Launcher按the_map.drones顺序寻找第一个非空提交后break；本局采用0号图，而不是评估所有同帧提交后自动取官方高分图。GUI会先执行本帧所有无人机控制，再判断是否结束，所以同帧双提交可以发生。SDK_SELECTION_EVIDENCE.json保留准确源码行和哈希。
- 与上一版三图候选录制轨迹比较，机体和炸弹状态的首个不同帧均为3442（接近旧局结束）；前3237帧全部一致。投弹确认步数完全相同，均10枚实投，墙覆盖分完全相同。扫描/导航路线退化不足以解释本次选中图退分。

由这些事实可以判断：这次多等203步，确实取得并重画了后期信息，但在线代理评分把较差旧图排在新图前面，同时提交又使0号较低分图进入官方计分。这是地图候选比较与提交协调的问题。反例通过只证明留时、缓存、重比和兜底契约，不证明代理排序能保证官方地图分单调提高。

**Map09能确认的事实：**

- 新候选4663步、0号交图，墙钟178.5974秒；本批最终版4853步、178.6125秒。两次均为墙钟兜底，并非本次180＋24普通交图出口主动结束。
- 新候选与本批最终版实际提交图的原始像素SHA256相同：082dc9e2f5f479fdb343c7da0feea0b9f3dea2f56c26d22d155e769efea17807。地图分、漏墙、误画、墙覆盖、探索率、10枚实投和总掉血均相同。
- 新候选红队小计43.3918，较本批最终版增加0.5026，增量全部来自交图步数减少190步的时间项；地图项和墙覆盖项贡献为0。这是在几乎相同墙钟预算下运行到不同步数的结果，不能据此认定实际计算更快或主动交图改善。
- 本局1号最后实投确认4344步；0号结束时仍只知道1号2832步库存1、3号2804步库存1。其他无人机也未取得全队清零确认；最终重比事件和普通交图提案均为0。投放确认仍在阻挡普通出口，硬兜底正常工作。
- 0号4230步和4590步的已有实时图继续参加比较，最终兜底使用4590版，Map09缓存更新没有丢失。

本轮不修改代码。若后续继续研究，应先判断在线排序与实际地图质量的偏差、以及多执行者同时提交的影响；仅继续增加留时，没有本次结果支持的直接收益。Map09普通交图仍受全队投放确认约束，不能把墙钟兜底的时间项波动当作该问题已解决。

本轮未改导航、扫描、地图拟合、投放复核或双时限兜底；实际运行前后源码哈希一致。个人原图和候选缓存完整性均已核验。

每图仅新增1局，三个对照是历史同种子结果。尤其Map09可能由墙钟兜底结束，负载变化会改变可运行步数与地图版本；不能把墙钟差异直接称为算法计算加速，也不能从单种子结果推断稳定提分。
