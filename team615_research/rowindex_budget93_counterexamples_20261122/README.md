## 实际行为

最大步数5400时，固定预算窗口为第5022至5051步，含首尾共30步。起点用整数上取整计算93%，不受消息、首次收包或首次就绪时间影响；不会重复开启。若极短赛制使该窗口与原末期窗口重叠，则关闭新预算窗口，保留旧机制。

新出口在control的库存同步及原硬兜底之后、原父控制器之前检查。未到提交时机或资格不满足时，继续原控制流程，不抢占导航，不新增配送。

参加预算竞价须同时满足本机previous_inventory=0、SDK当前库存=0、pending_drop为空、有已有非空缓存和原在线估计。近期明确剩弹报告会否决预算出口：来源步数距当前不超过360步、库存大于零。旧正库存、缺失记录保留为unknown，绝不改成零；已经确认零的旧记录继续有效。原_all_inventory_empty及普通交图的全队确认要求不变。

预算出口允许在预算到期时放弃无法确认的尾部投放机会；它不证明失联队友实际清零。若近期剩弹否决持续整个窗口，或者本机未清空/仍待确认/无缓存，则不强迫交图，之后继续原流程并保留原双时限兜底。

只复用现有缓存：优先当前group_best_image，其次个人backup_image，再其次已有deadline.image。提交时重新读取最新缓存；不调用扫描、融合、渲染、拟合或强制刷新。个人原图缓存不删除。竞价沿用原FinalMaps.rank及DeadlineSubmission的3步广播、按分排槽、剩余不超过4步的有界退出规则，使用独立预算窗口终点，不修改真实window_start。预算分数在首次取得资格时固定；无写死提交无人机。

red_map_bid只在预算窗口内加入对应就绪状态。预算与硬兜底使用独立状态，新增budget_submission_event、budget_submission_audit；记录窗口、提交图来源、未确认机号、库存原记录及team_confirmed，原deadline_submission_event不被冒用。原硬兜底始终先运行，1.5秒最小预留、长帧自适应预留、真实剩余4步兜底均保留。
