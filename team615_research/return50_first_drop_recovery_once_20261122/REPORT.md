# 50%返航候选：首弹脱离失败后一次性安全恢复

已实现并完成六类反例及既有功能回归。仅独立研究候选，不替换V16比赛基线；没有运行整场仿真、SDK比赛轮次或物理推进，没有新地图分数。

## 代码范围

- 基线：当前50%返航候选，SHA256 `e69ea77adb25b9ecbb8bd3a38f34f2241c35ad788c147aff67bc6d83e7c227e8`。
- 只改 `candidate/drop_departure.py` 和 `candidate/red_hooks.py`，其他54项payload逐字节相同。red_hooks除control接入外，其余方法AST不变。
- 50%返航、地图拟合、第二枚投放复核、选图协调、93%预算出口、库存实投确认和1.5秒墙钟预留保持。

## 实际实现

1. 首弹须由库存下降确认，当前位置与首弹定位可靠，确认还剩1枚且无待确认投放。原有脱离结束、仍距首弹不足32px，并连续30步停留在8px范围内，才有资格恢复。首弹投放时无可靠定位的记录不用于此恢复。
2. 每机首弹后最多一次；原始启动时间固定，最多62步或3秒墙钟，先到即退出。连续20帧净位移不足3px退出；可靠分离达到36px退出。进入需剩余至少82步和6秒，执行期间剩余墙钟不足3秒退出，且不让恢复跨入93%预算交图窗口。
3. 仅恢复内部识别自有首弹。语义BOMB、预测圆面交点、回波所在半径带必须一致；与其他已知炸弹表面重叠时不排除。正常导航与地图墙点不变。
4. 投前最近一帧可靠扫描在首弹确认时冻结，要求距离确认不超过2步，观测位置距投放点不超过8px。被炸弹遮挡的区域依然未知，须由该投前扫描证明整条23px宽度安全管道自由；检查整条管道而非只看中心线，保留采样和观测余量。当前新墙、其他炸弹、无人机及缺失观测可中止恢复。
5. 恢复只输出移动和零投放，不伪造库存、不新增投放记录、不安装全局航点。每帧复核定位、GPS跳变、里程计、当前障碍和预算。恢复接管点保留公共地图更新及消息处理，防止普通投放或快收尾覆盖恢复指令。
6. 硬墙钟/步数交图及93%预算出口仍在控制入口优先检查；不增加全队等待。因此不能保证其他机一定等待本机恢复完成，也不承诺必然补齐第10枚。

测试使用真实候选方法及真实SDK类型，输入为固定公开传感器/库存/消息夹具。完整control函数体保持原样，通过AST装入仅返回固定命令的基类，不调用探索导航基类、不启动Launcher或物理引擎。这不是地图运行，也不是历史轨迹驱动控制器重放。

服务器解释器Python3.11.17、NumPy1.26.4，沿用既有SDK和数值环境，没有安装或替换依赖。最终269项回执绑定最终候选SHA，服务器56项payload已重新核验。

开发期间失败原件在evidence中保留：旧夹具缺少新接口、滑动窗口反例构造问题已修正；候选补上圆周交点的浮点正数容差、严格圆面半径带识别，防止零距离伪交点或过近墙点误识别。后续又加入GPS跳变与首弹无可靠定位反例。最终结果以evidence/CHECK_RUN.json及四份最终JSON为准，不把早期PASS当作最终回执。
