# V16 候选图评分与解包：未达到收益门槛，停止路线

**最终决定：保持正式V16为基线，停止本次优化路线，不安排整场仿真。** 所有按单场真实比较次数加权的离线节省均不足1秒，最大仅约0.060秒。代码与验证材料仅作研究归档，不作为比赛新版本推荐。

## 修改范围

以正式V16为基线，仅修改map_candidates.py和red_hooks.py，其余54个文件逐字节相同。没有叠加此前bearing_core.py优化；导航、投放、地图拟合、比较触发频率、0.003近分规则、竞价及提交协调保持V16原样，墙钟预留仍为1.5秒。

三处优化：

1. np.unpackbits按有效像素数解包，删除后续同类型整图复制；评分网格抽样后再转布尔，整图空检查仍在抽样之前。
2. 一次choose()内部共享参考墙证据的膨胀结果和计数；上下文不跨轮次。local_score保留双参数调用，其他普通双参数评分回调继续按原约定调用。
3. choose()将本轮赢家已解包数组一次性交给install()，绑定owner、version、digest和packed对象；不匹配则原路解包，使用后清空。不会缓存跨帧评分结果。

## 等价验证

541项检查通过：300组固定种子的随机输入；空图、仅未抽样奇数位置有墙、填充位非零、非整齐尺寸、0.003近分、旧式回调、参考证据逐轮变化、赢家owner/version/digest/packed被替换、重复安装及修改已安装图片不污染后续解包等反例；另含108轮快照对照的普通/应急两种模式，共216组评分表、赢家、安装图片和版本信息对照。

必须区分原场历史与快照构造验证。已有日志没有保存每轮完整实时墙证据及所有被替换的旧候选图。我们从已保存图片、冻结快照和最终证据中恢复可用数据，通过重建digest尝试匹配原记录。只有参考证据摘要和每张候选图摘要同时匹配的轮次，才计入“原历史评分表精确复核”；其余使用明确标注的既有快照构造输入，仅验证新旧代码逐轮等价，不冒称原场精确重放。

## 离线耗时

每个计时批次恰好执行该份真实日志的比较轮数与逐轮候选数量，包含评分、解包、安装及原有不变的参考合并逻辑，固定已存快照/图片，不重新拟合。缺失历史输入的轮次采用上文标注的快照替代，因此这是按真实调用规模加权的离线估计，不是原比赛逐帧耗时。

同一进程、同一逻辑CPU 1、相同输入、预热后12组交替旧→新/新→旧配对，报告中位数。12次重复只用于计时稳定性，不把重复次数乘入单场节省；也不把不同地图的节省相加来跨过1秒门槛。

最近一次Map09输入规模下，链路局部约快36%，但整批只节省约0.049秒。在该离线基准中，原链路累计本身也只有约0.138秒，因此没有证据支持在这里争取数秒墙钟余量。不能将这36%说成整场加速36%。

运行环境Python3.11、NumPy 1.26.4、OpenCV 4.11.0；测量期间整机CPU平均忙碌率约11.35%～11.44%，两版均固定在同一预采样空闲逻辑核上。完整配对墙钟、进程CPU耗时及范围保存在BENCHMARK.json。
