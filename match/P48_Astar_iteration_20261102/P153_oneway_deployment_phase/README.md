# P153：先探索，再专心投放——首次小试结果

## 当前P48 A*怎样布点

无人机先用公共传感器探索并交换地图。协调机判断继续探索的预计收益是否值得付出时间与未投完风险，释放全部可用库存；原覆盖供应器在已知可达区域按新增墙体覆盖、路径预算、库存、间距和禁区选择目标并给每机排序。执行路径用A*，目标/布局距离计算仍有Dijkstra，布局还含原有界局部改进，不使用Gurobi。库存实际下降才确认投放，之后可重新分配余下目标。

当前并非完全严格两阶段：承诺检查可能退回探索、可选补扫和空载SORTIE仍可发生。用户提议本轮被实现为“收到有效投放计划后单向进入DEPLOY，不再主动探新目标”，保持原探索退出时机，传感/地图更新仍继续，失效任务可以重规划或回联络。不是同点同时投放，也不是等墙钟最后一刻才开始。通信按实际收到计划逐机切换，不假装全队同时得到消息。

## 实际小试

原42项底本只新增一个阶段helper和入口，32项协议/原方法检查通过后，完成唯一一次真实SDK作者CROSS测试。五机实际在264..266步切换，首切换前全部帧同底本；131次后续最终路线均为投放或回联络/hold，全部10次请求和库存下降发生在各自切换后。没有改地图渲染、布局、SDK、依赖或结束预算。

没有运行BLUE，小计不是完整红分，更不是五图均分。地图/逐机健康/收益门槛失败，保留首结果，不进入正式单图或五图、不晋级、不重跑救分。

父本69次承诺检查实际推迟为0，所以这个场景不能归因为消除了大量拖延。新3号首任务早12步接到，却先后释放目标并回联络，首次投放445延到840。0/3在363/364步各掉1健康；父本是1/4在344步各掉1，总损伤均2，不能说总碰撞损伤增加。具体释放分支/接触对象未采集，不能硬定为A*、禁区或拥堵。地图下降主要是误绘扣分增加1.6134pp，真实墙信用只下降.0533pp，不能简单说少探索漏了大片墙。

这不否定全部两阶段框架，只说明本次保持原切换时机、禁止再探索的具体适配没有优于底本。

## 是否最后一枚就结束

不是直接以最后一次请求投放结束。真实库存下降后才记录完成证书；正常还要本机空载、收齐全队完成证书、没有更优新鲜队友地图才提交。剩余预算耗尽则可以带余弹提交。此次最后一枚871步、872步提交；原场景777步、779步提交。结束预算和SDK规则保持。
